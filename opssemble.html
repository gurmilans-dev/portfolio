01 / Product

An event, split into areas that are ready or not.

An event is split into areas. Each area holds tasks, and problems on site become exceptions with a severity, so the question “are we ready?” has an answer computed from what is still open, area by area.

what it covers

  • StructureEvents, typed areas, tasks with priority, due dates and assignment
  • ExceptionsSeverity, a resolution trail and up to five private photo attachments
  • ReadinessPer-area and event-wide scores, blockers and timed checkpoints
  • On siteA My Shift queue, QR area workspaces and temporary guest sessions

02 / Readiness

Readiness is computed, and it shows its reasons.

Nobody sets readiness by hand. The server derives it from open work, per area and for the whole event, and every verdict comes with the rules that produced it.

Structure and exceptions

Areas contain the work and the problems.

Tasks carry a status, a priority and a due date. Exceptions record their severity, their resolution status and who resolved them.

Authorization

Every write is checked by the API.

Members hold one of four event roles (owner, coordinator, operator, viewer), and server-side checks decide what each role can change.

Readiness

The score is derived from open work.

A critical open exception or a blocked task blocks an area; ready needs every task done and no high or critical exception open.

Area access and records

QR access stays scoped and revocable.

Only the SHA-256 hash of each area token is stored. Reports, CSV exports, the activity log and the dashboard all read the same records.

Between ready and blocked, unfinished high or critical tasks keep an event in preparation. The score starts at 100 and loses 35 for each open critical exception, 25 for each blocked task, 10 for each unfinished high or critical task and 5 for each open high-severity exception. Each penalty is capped, and an event that is not ready cannot score above 95, so 100 always means ready.

key decision

Compute readiness from what is still open

Constraint
A coordinator needs to know whether an event can open, and a status someone sets by hand goes stale.
Decision
The server derives readiness from open tasks and exceptions, and lists the rules beside the verdict.
Result
A blocked event names the exception or task that blocks it, and the coordinator can see which rule applied.
Trade-off
The weights are fixed in code, so different rules need a code change.

03 / Access & security

Who can change what, event by event.

Roles are held per event, so the same person can coordinate one event and only view another. Owner, coordinator, operator and viewer are checked by the API on every write, next to input validation. On site, an area’s QR code opens just that area: a member signs in, or a permitted guest gets an expiring session scoped to that one area, which a coordinator can see and revoke at once.

area token lifecycle, revocable at any time

  1. MintOwner or coordinator issues an area token
  2. StoreOnly the SHA-256 hash persists
  3. ScanA member signs in, or a permitted guest gets an expiring area session
  4. ActActions scoped by the caller’s event role
Sessions
JWT sessions carried in HttpOnly cookies; passwords hashed with bcrypt.
Sign-in
Email and password with emailed verification codes, Google OAuth 2.0, password reset and an optional recovery email.
Enumeration & abuse
Generic login errors, failed-attempt delays and lockouts.
Tokens
Verification, reset and QR area tokens are stored only as SHA-256 hashes.
Evidence photos
Decoded and re-encoded to WebP without their metadata, stored outside public uploads, and served only after authorization.
Administration
Separate support, admin and superadmin tiers; high-impact actions need the current password and an emailed code.

backend hardening

  • Query safetyParameterized SQL across repositories
  • HTTP headersHelmet security headers and a CORS policy
  • UploadsFile validation by magic-byte signature
  • Rate & emailRequest rate limiting; transactional email via Nodemailer

04 / Live & offline

Live updates, and work that survives a lost connection.

Changes reach every open client of the same event through Server-Sent Events, with presence for who is viewing, and without adding a runtime dependency. Offline mode is behind a feature flag: an authorized event or guest area can be downloaded into IndexedDB, changes made without a connection wait in a durable outbox, and the server reconciles them with idempotent receipts and visible conflicts. API responses and private files are never put in the service-worker cache.

Behind those layers, the API is split into feature modules (events, areas, tasks, exceptions, readiness, live updates, offline sync, QR and guest access, AI assistance, reports and administration among them), each with the same route, controller, service and repository layers, plus shared plugins for the database, authentication, rate limiting, uploads and errors.

05 / AI assistance

Optional assistance, no write authority.

The application works without AI. When configured, an optional assistant service can draft, scaffold, explain, and summarize event content; results do not bypass normal write endpoints.

assistant capabilities

  • DraftingTask and exception drafts from a short prompt
  • Event scaffoldingSuggested areas and tasks for a new event
  • Gap & readinessGap checks, readiness explanations, and blocker summaries
  • Q&A & retrospectiveEvent question answering and retrospective drafting

06 / Tests & release

One build, from CI to staging.

The backend has 334 tests on Node’s test runner, plus ten MySQL integration tests that run separately; the frontend has 149 Vitest tests. Fifteen critical browser tests form the release gate: CI builds one release artefact and runs them against that exact build, in Chromium and in WebKit with phone and tablet profiles, before the artefact can be promoted.

Deploying to staging is a separate, manual workflow. It accepts only the artefact of a successful CI run on main, checks its SHA-256 checksum and installs that same build over SSH with a pinned host key, without rebuilding it.

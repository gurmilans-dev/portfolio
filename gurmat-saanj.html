It follows the live recitation of Gurbani, the hymns of the Sikh scripture, and keeps the projector and the Sangat, the congregation, on the same line: one editor controls the display, and anyone can follow on their own phone.

01 / Product

One live line, read across the room.

I built the React and JavaScript interface, Node.js and Express API, matching flow, and multi-device session. Participants join by QR or session code; phones follow the projector without becoming extra control surfaces.

Two live modes share one tracker. Kirtan follows a sung Shabad (a hymn) line by line; Katha follows a speaker across nearby Shabads or a whole Ang (a page of the scripture), and holds while they explain. Away from the microphone, a Shabad can be found by first letters, Ang number or meaning. Search by meaning uses a multilingual embedding index built ahead of time: only the query is embedded, in the browser, with the multilingual-e5-small model running on ONNX Runtime’s WebAssembly backend through Transformers.js, and Shabads are ranked by cosine similarity. Bani mode, the daily Hukamnama (the day’s reading) and offline session packs sit beside the readers.

Recognition path

Speech input produces candidates, not display text.

The transcript is normalized, checked against BaniDB, and scored before the application selects a known line.

Application selection

Uncertain input can hold the current line.

Matching and confidence handling decide whether the application advances; raw transcript text never reaches the display.

Shared line, local display

Projector and viewers follow the same selected line.

Viewer font, size, language, and translation settings stay on each device and do not change the projector.

Editor ownership

Control changes only after approval.

A second device may request control, but remains a viewer until the current editor or main application approves the transfer.

03 / Application decision

Keep uncertain recognition away from the display.

key decision

Keep known text and final selection under application control

Context
Recognition can be noisy; known lines can be textually close.
Decision
Fuzzy scores and confidence handling narrow BaniDB candidates before anything reaches the display.
Reason
Known text and projector authority remain in the application.
Trade-off
Uncertain input sometimes holds rather than advances.

04 / Pairing & control

A phone controls the projector only with a credential the server issued to it.

The remote controller, Sangat View and the laptop presenter view were hardened together. Each way of joining grants exactly one level of access, and every command from a phone carries a token the server minted for that device.

Trusted device
Scanning the host's QR code enrolls a trusted device; the link expires after five minutes. The first trusted device takes control when it is free, and later ones request a handoff.
Typed code
A four-digit code enrolls a view-only device. Codes are random, expire, rotate on their own and are throttled per source; control waits for the host or current controller to allow it.
Device token
Each paired phone authenticates with its own token, so a rotating code never disconnects it.
Host stream
The host's command stream opens with a single-use ticket valid for 30 seconds, so the host token never appears in a URL.
Revocation
New code revokes every paired device and Sangat View link, and open Sangat View pages say that their link has expired.
Presenter view
The laptop keeps the full reader while a separate output window fills the projector. It is placed on that display where the browser allows it, and reused across readers.

05 / Limits

What it depends on

Browser dependency
Speech recognition availability and behaviour are platform-dependent.
Room conditions
Noise, overlapping speech, and pronunciation weaken transcripts.
Matching limit
Similar lines and language variation remain ambiguous; a score is not proof.
Display control
One approved editor operates the projector; viewers cannot override it.
Pairing state
Pairing lives in the server's memory: a restart ends it and invalidates Sangat View links.
Operating context
A working setup spans microphone permissions, browser support, the Node service, BaniDB, projector output, and connected devices.

API controls

The API also uses Helmet, CORS, rate limiting and input validation, and every remote command is authenticated.

06 / Evaluation

What is tested, and what is not measured yet

recognition accuracy

Still unmeasured: no authentic recording has yet been scored against independently verified, synchronized labels. The tooling for it exists: opt-in traces of matching and navigation decisions, audio-and-trace capture bundles, a local review page, and an evaluator that scores a trace against reviewed labels. Synthetic scores check that tooling, not live accuracy.

automated tests

The suite has 447 tests: 125 backend tests, including remote authentication, stream tickets, Sangat View revocation, device enrollment and suggestion ranking, all run without calling BaniDB, and 322 frontend tests covering recognition, tracking, capture, evaluation and replay.
